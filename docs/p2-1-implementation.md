# P2-1 实施记录：个人档案与偏好中心

## 阶段目标

面向个人长期使用，把长期个人信息从对话上下文和长期记忆中独立出来，并在用户明确授权后复用到 Grill 追问和回答上下文中。

## 实际实现

### 1. 数据层

- 新增 `user_profiles` 表，保存基本信息、健康目标、饮食偏好和授权状态。
- 新增 `user_profile_events` 表，记录档案更新动作和字段名，不保存敏感值的前后内容。
- 新增 `migrations/versions/0007_personal_profile.py`。
- 个人档案与 `conversations`、`user_memories` 分离，避免把临时对话误当成长期偏好。

### 2. Profile Service

新增 `core/profile.py`：

- 对身高、体重、年龄、活动量、目标等字段进行约束校验。
- 默认拒绝未授权的档案写入。
- 撤回授权或删除档案时清空档案内容。
- 只为已授权用户生成 Workflow 上下文。
- 将健康目标和过敏信息映射为 Grill 可识别的偏好字段。

### 3. API

新增接口：

```text
GET    /me/profile
PUT    /me/profile
POST   /me/profile/consent
GET    /me/profile/export
DELETE /me/profile
```

所有接口复用现有 JWT 用户身份和用户隔离机制。

### 4. Grill 和 Workflow

- `ConversationRuntime` 每轮加载当前用户已授权的档案。
- 档案字段以 `preference` 来源预填 Grill 上下文。
- 用户本轮明确输入的字段优先级高于档案值。
- `advice` 和普通问答不会因为有个人档案就强制进入餐单规划。
- 未授权个人档案不会进入模型上下文。

### 5. 前端

新增 `/profile` 页面：

- 基本信息编辑
- 健康目标设置
- 过敏原和饮食偏好设置
- 个人档案授权
- 清空个人档案
- 返回聊天页面

聊天页面增加“我的档案”入口。

## 当前边界

- 当前通过页面主动填写和修改档案，暂不自动从对话中提取并保存新偏好。
- 当前不引入多租户、复杂 RBAC、企业 SSO 或独立用户画像服务。
- 当前档案用于营养建议上下文，不构成医疗诊断或处方依据。
