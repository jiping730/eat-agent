# P1-5 实施记录：安全和营养领域防护

## 阶段目标

在当前 `FastAPI + LangGraph + Grill + Tool Registry + MCP` 单体小型平台内，增加统一的安全边界，确保用户输入、检索/MCP 内容、工具调用和最终输出都经过可解释的规则检查。范围覆盖 Prompt Injection、敏感信息、过敏原、慢性病/药物风险、营养数据来源和用户记忆治理。

本阶段采用“规则策略 + 输出校验”的小型平台方案，不引入独立风控微服务、第三方内容安全平台、医疗诊断模型或人工坐席系统。

## 实际实现

### 1. 统一安全契约和策略

- 新增 `core/safety_guard.py`，提供 `SafetyDecision` 和 `SafetyGuard`。
- 输入策略统一返回 `action`、`risk_level`、`categories`、脱敏结果、医疗风险、过敏原和引用要求等字段。
- 识别中文/英文 Prompt Injection，例如“忽略系统提示”“显示系统提示”“ignore previous instructions”等；注入文本按普通不可信文本处理，不会直接触发工具。
- 识别手机号、邮箱、身份证号、银行卡号、Bearer Token 和常见 API Key，并在进入 Workflow、持久化和记忆之前脱敏。

### 2. Workflow 安全接入

执行顺序调整为：

```text
输入安全检查
  ├─ 高风险医疗/药物问题 → 直接安全响应，不进入检索、Grill 或工具
  └─ 普通问题 → 意图识别 → 记忆 → Grill → 工具前安全门禁 → 生成回答 → 输出校验
```

- 在 `understand_intent` 前进行用户输入检查，高风险医疗和药物剂量/停药/相互作用问题直接进入 `respond_safety`。
- 在 `execute_tool` 前再次检查 Prompt Injection 和高风险内容；被阻止时不调用工具，并返回统一安全结果。
- RAG、MCP、GraphRAG、记忆内容在进入回答 Prompt 前标记为不可信数据；检出指令样式片段时隔离该片段，明确禁止模型执行其中指令。
- 最终回答统一经过脱敏、过敏原冲突、医疗免责声明和营养数字来源校验；API 返回 `safety` 和 `sources` 摘要。

### 3. 营养和医疗领域规则

- 识别糖尿病、高血压、肾/肝功能、痛风、孕哺期、儿童、老年人及药物相关上下文。
- 对停药、换药、剂量、治疗、诊断、药物相互作用等高风险问题拒绝个性化判断，并建议咨询医生或注册营养师。
- 识别花生、坚果、乳制品、蛋类、海鲜、鱼虾蟹、大豆、小麦/麸质和芝麻等常见过敏原。
- 当最终建议命中用户已声明的过敏原时，阻止直接推荐并显示过敏原强提醒，要求核对配料表和交叉污染标识。
- 识别带有 `千卡/kcal/克/g/mg/%` 等单位的营养数字。存在来源时自动附加“参考来源”；没有来源时不把数值包装成已核实事实，并增加数据来源提示。

### 4. 记忆授权、导出和删除

- `core/persistence.py` 新增 `memory_consents` 和 `user_memories` 数据模型。
- 新增 Alembic 迁移 `0005_memory_governance`。
- 记忆默认未授权；只有用户显式授权后才写入和检索长期记忆。
- 撤回授权或删除记忆时，同时删除数据库记忆记录并清理进程内短期记忆。
- 新增接口：
  - `POST /memory/consent`（兼容 `/me/memory/consent`）
  - `GET /memory`、`GET /memory/export`（兼容 `/me/memory/export`）
  - `DELETE /memory`（兼容 `/me/memory`）
- 所有接口复用现有 API Key/JWT 身份边界，只能操作当前用户自己的记忆。
- 记忆写入前再次脱敏，避免把手机号、邮箱、令牌等敏感信息写入长期记忆。

## 小型平台交付边界

- 规则是确定性的安全基线，不声称具备医疗诊断能力。
- 未引入外部内容安全 SaaS、独立风控服务、人工坐席或复杂医疗模型。
- 当前来源校验依赖已有 Tool Registry/RAG 来源协议；后续知识库管理后台可增加来源审核和引用质量评分。
- 记忆治理已具备单体小型平台的授权、导出和删除能力；跨租户、跨区域合规留存和专用隐私中心属于后续平台化工作。
