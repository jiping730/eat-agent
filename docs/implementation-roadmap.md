# 项目实施主线与优先级清单

> 本文是当前项目后续开发的唯一主线基线，依据“个人长期使用的小型平台”目标整理。
>
> 后续开发必须严格按本文的优先级和阶段顺序推进。已完成的历史阶段记录见 [implementation-record.md](implementation-record.md)，历史记录不能替代本文主线。

## 1. 总体技术主线

最终技术方向收敛为个人小型平台的单体架构：

```text
FastAPI
  + LangGraph
  + Grill 追问引擎
  + SQLite（默认）/ PostgreSQL（可选）
  + FAISS + 词法检索
  + LiteLLM
  + 本地 MCP
  + JSON 日志与基础健康检查
```

当前的 ReAct、旧 Skill 和 MCP 都作为能力接入，不再各自发展成独立 Agent 主链路。GraphRAG、Qdrant、Langfuse 和 OpenTelemetry 不属于当前项目主线。

## 7. 明确不做的企业级扩展

- 不要同时引入多个 Agent 框架
- 不要先做复杂 GraphRAG
- 不要先上 Kubernetes
- 不要继续堆更多 MCP Server
- 不要在没有评测集前频繁更换模型
- 不要在没有会话持久化前扩展复杂记忆
- 不要在没有 Tool Policy 前开放任意工具调用
- 不做万人级多租户、企业 SSO、复杂 RBAC 和独立 IAM
- 不做 Kubernetes、多副本、自动扩缩容、灰度发布和跨区域容灾
- 不做 Celery、Temporal、分布式索引任务和大规模知识图谱构建
- 不做 GraphRAG 正式建设、独立向量数据库和微服务拆分
- 不做 Langfuse、OpenTelemetry、服务网格和集中式成本平台

当前最重要的主线是：

```text
统一 Workflow
→ 会话与个人档案
→ 小众平台租户隔离
→ Grill 规则稳定
→ API 安全
→ 工具可靠
→ RAG、模型与流式体验
→ 安全与知识库
→ 个人历史、质量回归和本地备份
```

完成 P0、P1 和 P2-1 后，项目已经达到个人长期使用的小型平台目标；后续优先完善小众平台租户隔离、体验、质量和数据可控性，而不是建设万人级基础设施。

### 项目长期执行边界

本项目以个人长期使用和少量租户的小众平台为边界，默认单机、单体、Docker Compose 可选部署：

- SQLite 是默认数据库，PostgreSQL 只是可选升级路径；
- 本地 FAISS 和同步知识库构建足以支撑当前规模；
- JWT/API Key 满足当前身份边界，P2-5 增加基础租户和角色隔离，不引入企业身份中心；
- 备份采用本地文件导出和恢复，不建设云端容灾平台；
- 新增需求必须先证明个人或小众平台场景确实需要，才能进入主线。

本轮交付后的实际主线是：

```text
统一 Agent 边界
→ 会话与个人档案
→ Grill 追问稳定
→ 模型、工具和 RAG 质量
→ 安全与可解释回答
→ 个人知识和历史管理
→ 本地备份、恢复与升级
```
